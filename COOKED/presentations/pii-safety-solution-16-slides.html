Один endpoint.
Два обязательных поля.

Запрос

POST /process

{
  "payload": "email ivan@example.com",
  "payload_id": "demo-1"

Ответ

{
  "result": "email {{EMAIL_1}}"

payload — текст.
payload_id — ключ состояния обработки.

Иллюстрация формата. При восстановлении передаётся текст с токенами и тот же идентификатор.

Структурированные данные

Email, телефон, ИНН, карта, паспорт и другие типы. Для ИНН — контрольные суммы; для карты — алгоритм Луна.

ФИО, даты и адресные поля: признаки поля, принадлежности человеку, публичного или технического контекста.

Границы записей и расстояние в токенах ограничивают перенос контекста. Позиции относятся к исходному тексту.

PII Safety Module / 08 / Качество детектора

Персональный контекст

«заявитель», «владелец»

Такие признаки помогают подавлять неподходящие кандидаты.

PII Safety Module / 09 / Маскирование

Токен хранит тип.
Vault хранит значение.

email ivan@example.com
↓
email {{EMAIL_1}}

Стабильность

Одинаковые тип и точное значение в одном тексте получают один токен.

Точность замены

Замены выполняются по позициям сущностей. Остальной текст сохраняется.

Обратимость

При демаскировании заменяются только токены, присутствующие в mapping.

PII Safety Module / 10 / Повторные запросы

payload_id связывает весь цикл

Записи ещё нетdetect → mask → атомарное сохранение → результат
Запись есть, хеш совпалВернуть прежний masked_result — повтор маскирования
Запись есть, хеш отличаетсяВосстановить известные токены через сохранённый mapping

Redis SET NX EX разрешает гонку первого сохранения. В текущей версии любой другой текст с существующим ID идёт в ветку восстановления; отдельной ошибки конфликта ID нет.

PII Safety Module / 11 / Хранилище соответствий

Шифрование и ограниченное
время жизни

AES256-GCM

Mapping шифруется до записи. payload_id включён в аутентифицируемые дополнительные данные.

900секунд TTL по умолчанию

Redis удаляет запись по TTL. После истечения соответствий восстановить значения из этой записи нельзя.

Для перезапуска и нескольких реплик нужен общий постоянный MAPPING_ENCRYPTION_KEY. Без него создаётся временный ключ процесса. Шифруется mapping; masked_result и метаданные хранятся отдельно.

Проверка сервиса

/health/live и /health/ready.

PII Safety Module / 15 / Итог

Рабочее ядро защиты
на границе с LLM

Что реализовано

Единый API, детерминированное обнаружение, обратимые токены, повтор запросов и зашифрованный mapping с TTL.

Что требует развития

Подключение политик потребителей, полноценная наблюдаемость, обработка отказов Redis и дополнительная проверка качества на новых текстах.

Найти → заменить → обработать в LLM → восстановить

Граница версии: consumers.yaml ещё не участвует в обработке; внешняя LLM подключается приложением. Качество обнаружения остаётся измеряемой характеристикой, а не гарантией отсутствия пропусков.
