# Текущая спецификация требований

Единственная актуальная спецификация требований проекта. Этот файл всегда содержит актуальные требования. Перед изменением предыдущая редакция сохраняется отдельным неизменяемым снимком (например `current_specification-v2.md`).

## Правила
- Неподтвержденные предложения не выдаются за согласованные требования.
- Каждое требование имеет карточку (см. `playbooks/manage_requirements.md`).
- Статус согласования: `предложено | согласовано | отклонено`.

## Шаблон карточки
```yaml
REQ-001:
  потребность: <какую потребность закрывает>
  роль: <для какой роли>
  сценарий: <сценарий использования>
  поведение: <ожидаемое поведение>
  ограничения: <ограничения и допущения>
  источник: <SRC-NNN / CH-SRC-NNN-NN>
  статус_согласования: предложено
  критерии_приемки:
    - AC-ID: <AC-001>
      описание: <проверяемый критерий>
```

## Правила ID
- Требования: `REQ-001` (глобально уникальные).
- Критерии приемки: `AC-001` (глобально уникальные).
- Следующий номер = максимальный занятый + 1; перед созданием проверяй занятые ID.
- Старые не перенумеровывай, занятые не используй повторно.
- Полные правила — `database/working/id_rules.md`.
