# Тестирование

Описание тестирования проекта: сценарии, критерии, окружения. Собирается из чанков и источников.

## Формат записи
```yaml
сценарий:
  описание: <что проверяется>
  критерии: <критерии успеха>
  источник: <SRC-NNN>
```

## Сценарии
```yaml
проверка_качества_кода:
  описание: Автоматическая проверка после загрузки решения в ZIP; проверяется исходный код.
  критерии: решение проходит проверку качества кода; иначе не учитывается
  источник: SRC-002

нагрузочное_тестирование:
  описание: Проверяющая система подаёт нагрузку по эталонному датасету на POST /process; оценивает точность маскирования/демаскирования и поведение под нагрузкой.
  критерии: точность маскирования и демаскирования, поведение под нагрузкой; таймаут 10 с, ретраи до 2, 429 допустим, стоп после 5 невалидных запросов
  источник: SRC-001

проверка_маскирования:
  описание: Прямая проверка — система шлёт исходную строку с новым payload_id, сервис возвращает маску.
  критерии: сравнение с эталонной маской (нормированное span-based расстояние Левенштейна [0..1])
  источник: SRC-001

проверка_демаскирования:
  описание: Обратная проверка — система шлёт маску с тем же payload_id, сервис возвращает исходную строку.
  критерии: сравнение с исходной строкой из датасета (span-based логика)
  источник: SRC-001
```

## Требования к надёжности при тестировании
- Таймаут одного запроса — 10 секунд.
- Ретраи — до 2 на каждый запрос (итого до 3 попыток); эндпоинт идемпотентен по payload_id.
- 429 (Too Many Requests) допустим под нагрузкой; учитывается Retry-After.
- 429 не увеличивает и не сбрасывает счётчик невалидных запросов; успешный ответ сбрасывает счётчик.
- Если 429 не проходит на маскировании — демаскирование по этому элементу не запрашивается; если на демаскировании — учитывается, проверка продолжается.
- Стоп при недоступности: после 5 невалидных запросов подряд.
- Прогон ~5 минут, целевой RPS 1000, latency не более 1 с (ориентир).

## Неоднозначность: latency как требование и как ориентир
- В ТЗ (SRC-001): Latency не более 1 секунды — требование.
- В Приложении B (SRC-001): latency не более 1 с — ориентир, не жёсткий лимит.
- Таймаут проверки 10 секунд не заменяет целевой latency. Требуется уточнение (см. Q-003).
