# Архитектура

Описание архитектуры проекта: компоненты, взаимодействия, технологии. Собирается из чанков и источников.

## Формат записи
```yaml
компонент:
  роль: <назначение>
  взаимодействия: <с кем/чем связан>
  технологии: <используемые технологии>
  источник: <SRC-NNN>
```

## Компоненты продукта
```yaml
модуль_безопасности_ПД:
  роль: Прокси между системой-потребителем и LLM; идентификация, маскирование, демаскирование ПД.
  взаимодействия: система-потребитель, LLM
  технологии: не ограничены (см. «Инструменты разработки»)
  источник: SRC-001

система_потребитель:
  роль: Отправляет запросы в LLM через модуль; получает обработанные ответы.
  взаимодействия: модуль безопасности ПД
  технологии: не ограничены
  источник: SRC-001

LLM:
  роль: Внешняя модель, к которой обращается система-потребитель через модуль; получает замаскированные запросы.
  взаимодействия: модуль безопасности ПД
  технологии: не фиксированы в ТЗ
  источник: SRC-001

эндпоинт_process:
  роль: Единый HTTP-эндпоинт POST /process для маскирования и демаскирования.
  взаимодействия: проверяющая система нагрузочного тестирования
  технологии: HTTP/HTTPS (self-signed допускается)
  источник: SRC-001
```

## Инструменты разработки (не архитектура продукта)
- **Модель для разработки**: участникам предоставлен доступ к DeepSeek V4 Flash через платформу «Альфа-Ген» на время хакатона. Это инструмент для разработки решения, а не обязательная модель, которая должна работать внутри сервиса.
- **IDE**: рекомендуется VS Code, Kilo Code.
- **Языки**: рекомендуется Python, Java, Go (рекомендация из брифинга, SRC-004). Другие языки проверяются, но на этих удобнее.
- Использование своих кодинговых агентов крайне не рекомендуется (пайплайн проверки выстроен под рекомендуемые инструменты).

## Архитектурные требования
- Архитектура должна позволять добавлять новые правила и сценарии без переделки всего сервиса.
- Масштабируемость: допускает добавление настроек для новых типов ПД и увеличение RPS при сохранении Latency.
- Архитектура для высокого RPS — на усмотрение (репликация, распределение нагрузки, очереди).
