# Безопасность и эксплуатация

## Статус утверждений

### Факты из задания

- Требуются отсутствие утечек, шифрование и минимизация данных; целевое качество —
  не менее 95%, latency — не более 1 секунды, RPS — не менее 1000
  ([источник](../RAW/requirements.md)).
- Проверка выполняется по span-based логике
  ([источник](../hackathon_database/evaluation_criteria.md)).
- Временный туннель для локально развёрнутого решения допустим на период проверки,
  если уведомить организаторов
  ([источник](../RAW/2026-09-22-opening-transcript.txt)).

### Реализованные решения

- Две API-реплики работают за Nginx и используют общий Redis; readiness включает
  Redis `PING` ([конфигурация](docker-compose.yml)).
- Значения для обратного маскирования шифруются AES-GCM до записи в Redis; общий
  ключ создаётся при первом запуске и монтируется в API read-only
  ([реализация](app/vault/crypto.py), [инициализация](app/key_init.py)).
- Записи имеют TTL, Redis ограничен по памяти, request body ограничивается до
  JSON-парсинга, а конфликтующее повторное использование `payload_id` получает 409.
- Контейнеры используют read-only root filesystem, drop-all capabilities,
  `no-new-privileges` и лимиты CPU, RAM и PID.
- `/process` может проверять `X-API-Key` через `PROCESS_API_KEY`. Внешний защищённый
  контур дополнительно должен обеспечивать TLS, управление идентичностями и секретами.
- Метрики имеют фиксированные labels и не содержат payload, result, `payload_id`
  или распознанные значения. Доступны request/error counters, latency histogram,
  in-flight gauge и агрегированный счётчик принятых символов.
- Runtime-зависимости устанавливаются из `uv.lock` с проверкой hashes; базовые
  Docker-образы закреплены по digest.

### Ограничения и недоказанные утверждения

- Внутренние стандарты ИБ Альфа-Банка команде не предоставлены. Поэтому решение
  нельзя честно объявить соответствующим этим стандартам без официального профиля
  требований, проверки банка и приёмочного заключения.
- Compose защищает демонстрационный host-контур, но Nginx и Redis остаются
  одиночными инфраструктурными компонентами. Для production нужны отказоустойчивые
  ingress и Redis/совместимое хранилище, оркестратор, резервирование и мониторинг.
- HTTP на loopback и временный публичный туннель подходят только для portal-теста.
  Они не являются защищённым банковским периметром.
- Локальный benchmark и blind holdout дают воспроизводимую оценку, но не раскрывают
  результат на закрытом датасете портала. Закрытое качество подтверждает только портал.

## Операционные проверки

```bash
.venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/mypy app
docker compose up --build -d
tests/integration/test_compose_failover.sh
PROFILE=load TARGET_HTTP_RPS=1000 k6 run tests/load/process.js
```

При сборе метрик двух реплик Prometheus должен опрашивать `api1:8080/metrics` и
`api2:8080/metrics` отдельно из сети `edge`; endpoint через proxy возвращает метрики
только выбранной реплики.
