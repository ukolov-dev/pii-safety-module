# Эксплуатация восстановленной версии v3.26

Этот документ описывает текущие файлы восстановленной сборки v6.

- Compose запускает одну реплику API и Redis; порт API опубликован как `8080:8080`
  ([конфигурация](docker-compose.yml)).
- Данные для обратной замены масок шифруются AES-256-GCM; записи имеют TTL
  ([шифрование](app/vault/crypto.py), [настройки](app/settings.py)).
- Без `MAPPING_ENCRYPTION_KEY` создаётся временный ключ процесса. После перезапуска
  сохранённые записи нельзя расшифровать. Постоянный ключ нужно передавать через
  окружение процесса API; текущий Compose не передаёт эту переменную автоматически.
- Без `REDIS_URL` используется память одного процесса
  ([выбор хранилища](app/vault/factory.py)).
- `/health/ready` проверяет инициализацию сервиса; отдельный Redis PING в этой версии
  не выполняется ([API](app/main.py)).
- В этой сборке нет проверки `X-API-Key`, endpoint `/metrics`, Nginx и двух реплик API.
  Для внешнего защищённого развёртывания TLS и аутентификация обеспечиваются отдельным
  входным шлюзом. Конфигурация хакатона сама по себе не подтверждает соответствие
  внутренним стандартам банка.

Исходный код и конфигурация восстановлены из v6. Нагрузочные результаты в
[`benchmark-results/v6/`](benchmark-results/v6/IMPROVEMENT_REPORT.md) относятся к
историческому прогону; перед публикацией повторно выполняются проверки, перечисленные
в [`VERSION.md`](VERSION.md).
