# Обработка результатов тестирования

Процедура обработки результатов тестирования по чеклистам приемки.

## Статусы результата
- **принято** — все критерии успешно пройдены и приняты.
- **частично принято** — часть критериев пройдена; закрывай только успешно пройденные и принятые.
- **требует доработки** — есть проваленные критерии.
- **не проверялось** — критерии не проверялись; переноси дальше.
- **заблокировано** — проверка невозможна из-за блокера.
- **требуется решение** — нужен ответ/решение участников.

## Правила
- Закрывай только успешно пройденные и принятые критерии.
- Проваленные, заблокированные и непроверенные сохраняй открытыми.
- Непроверенное переноси дальше (не закрывай).
- Код, выкладку и бизнес-приемку учитывай отдельно.

## Место сохранения
- Каждый результат — отдельный файл `database/working/test_results/RES-001.md`.
- Добавь запись в индекс `database/working/test_results/index.md`.
- Обнови матрицу трассируемости `database/working/traceability_matrix.md`.
- ID результатов — по `database/working/id_rules.md` (`RES-`).

## Формат записи результата
```yaml
RES-001:
  чеклист: <CHK-001>
  задача: <TASK-001>
  окружение: <окружение проверки>
  сборка: <идентификатор проверенной сборки>
  статус: <принято | частично принято | требует доработки | не проверялось | заблокировано | требуется решение>
  пункты:
    - AC-ID: <AC-001>
      предусловия: <что должно быть готово до проверки>
      шаги:
        - <шаг 1>
        - <шаг 2>
      ожидаемый_результат: <что должно получиться>
      фактический_результат: <что получилось>
      статус: <принято | провалено | заблокировано | не проверялось>
      комментарий: <примечания>
  код: <статус проверки кода>
  выкладка: <статус выкладки>
  бизнес_приемка: <статус бизнес-приемки>
```

## Порядок работы
1. Получи результаты тестирования.
2. Сопоставь с пунктами чеклиста по `AC-ID`.
3. Проверь занятые ID в `test_results/index.md`; выдай следующий номер.
4. Заполни фактический результат и статус каждого пункта.
5. Закрывай только успешно пройденные и принятые критерии.
6. Проваленные, заблокированные и непроверенные сохраняй открытыми.
7. Переноси непроверенное дальше.
8. Учитывай код, выкладку и бизнес-приемку отдельно.
9. Каждая повторная проверка критерия получает собственный `RES-` и сохраняет историю предыдущих результатов.
