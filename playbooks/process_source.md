# Процесс обработки источника

Процедура разбора исходного материала из `RAW/` на смысловые чанки.

## Разделение баз знаний
При обработке сырого документа определи, к какой базе знаний относится материал:
- **Регламент проведения хакатона** (правила, инструкции, критерии оценки, расписание) → `hackathon_database/`.
- **Требования к самой системе** (всё, что не касается регламента проведения хакатона) → `database/`.

## Порядок обработки
1. **Регистрация** — добавь запись `SRC-NNN` в реестр источников соответствующей базы (`database/registry_sources.md` или `hackathon_database/registry_sources.md`).
2. **Чанки** — прочитай источник, разбей на смысловые эпизоды, создай файлы в `chunks/` соответствующей базы по шаблону `_template.md`, добавь записи в `chunks/index.md`.
3. **Тематические знания** — перенеси новую информацию из чанков в тематические файлы соответствующей базы. Переноси только новую информацию, сохраняй ссылки на источники.
4. **Глоссарий** — выяви значимые термины и добавь их в глоссарий по `playbooks/maintain_glossary.md`.
5. **Решения и вопросы** — зафиксируй согласованные решения в `registry_decisions.md` (`DEC-NNN`) и открытые вопросы в `registry_questions.md` (`Q-NNN`) соответствующей базы.
6. **Покрытие** — отметь покрытие в `registry_coverage.md` (`COV-NNN`) соответствующей базы: источник, обработанные диапазоны, связанные чанки, пропуски, оставшуюся часть, точку продолжения. Статус источника в реестре источников — «в обработке» или «обработан» (см. ниже).

## Точные локаторы
- Для транскрипта указывай спикера, таймкод и строки.
- Для PDF указывай страницу и раздел.
- Для текстовых файлов указывай раздел/строки.

## Двойной проход по источнику
- Проходись по сырому файлу **дважды**.
- Первый проход — извлечение смысловых эпизодов и создание чанков.
- Второй проход — самопроверка на предмет упущенного контекста и требований.
- Не ищи явные маркеры («система должна...») — требования могут быть скрыты в описательных абзацах.

## Работа с дублирующимися чанками
- При создании чанка **всегда проверяй индекс** `chunks/index.md` соответствующей базы.
- Если эпизод уже покрыт существующим чанком — не создавай дублирующий чанк.
- Если новый источник дублирует уже обработанный материал — свяжи с существующим чанком, а не создавай копию.
- Если новый источник **уточняет** существующий чанк — дополни существующий чанк, сохранив ссылку на новый источник.
- Если новый источник **радикально меняет** существующее требование — это открытый вопрос (`Q-NNN`), задай его для разрешения конфликта.

## Статусы источника
- **в обработке** — разбор незавершён, есть оставшаяся часть.
- **обработан** — полное покрытие проверено, пропусков нет.

Статус «обработан» ставь только после проверки полного покрытия. Для незавершённого разбора используй «в обработке».

## Чек-лист самопроверки перед закрытием источника
Перед переводом источника в статус «обработан» проверь:
- [ ] Все смысловые эпизоды извлечены (двойной проход выполнен).
- [ ] Каждый чанк имеет корректный ID `CH-SRC-NNN-NN` и добавлен в `chunks/index.md`.
- [ ] Нет дублирующих чанков (индекс проверен).
- [ ] Все неоднозначные фрагменты помечены как открытые вопросы (`Q-NNN`).
- [ ] Все ссылки на источники проставлены.
- [ ] Покрытие отмечено в `registry_coverage.md` (диапазоны, пропуски, оставшаяся часть).
- [ ] Полное покрытие проверено по конкретным диапазонам.

Статус «обработан» ставь только после проверки полного покрытия по конкретным диапазонам. Пока проверка не завершена, не пиши «пропусков нет».

## Примечание
- Обработка источника сама по себе не создает задачи разработки.
- После значимых изменений обновляй `database/current_context.md`.

## Определение чанка
Один чанк = один смысловой эпизод:
- решение,
- требование,
- вопрос,
- замечание.

## ID чанка
Формат: `CH-SRC-NNN-NN`
- `SRC-NNN` — источник, из которого взят чанк.
- `NN` — порядковый номер чанка в источнике (01, 02, ...).

## Поля чанка
- **источник** — `SRC-NNN`.
- **точный локатор** — место в источнике (строка, раздел, страница, временная метка).
- **тема** — краткое название эпизода.
- **краткое содержание** — суть эпизода.
- **статус** — `новый | в работе | обработан`.
- **связанные требования и вопросы** — ссылки на требования и `Q-NNN`.

## Обработка больших источников
- Большие источники обрабатывай частями.
- Отмечай покрытие каждой части в `registry_coverage.md`: обработанные диапазоны, связанные чанки, пропуски, оставшуюся часть, точку продолжения.
- Сохраняй смысл на границах чанков: не разрывай эпизод посередине, при необходимости дублируй контекст в соседних чанках.
- При продолжении разбора проверяй дубли: не создавай повторные чанки для уже обработанных участков.
- **Всегда проверяй индекс** `chunks/index.md` перед созданием чанка.
- Статус «обработан» ставь только после проверки полного покрытия; для незавершённого разбора используй «в обработке».
