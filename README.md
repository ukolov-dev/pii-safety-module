# PII Safety Module v3.26 — защита персональных данных для LLM

Сервис распознаёт персональные данные, заменяет их обратимыми масками и
восстанавливает исходные значения через единый `POST /process`.
Реализация, тесты и конфигурация запуска находятся в [`solution/`](solution/README.md).

Опубликована восстановленная сборка с детектором **v3.26** из архива v6.
Состав версии и результаты проверок — в [`solution/VERSION.md`](solution/VERSION.md).

## Быстрый запуск

```bash
git clone https://github.com/ukolov-dev/pii-safety-module.git
cd pii-safety-module/solution
docker compose up --build
```

Сервис доступен на `http://127.0.0.1:8080`.
Подробности API, локальной установки и тестирования — в
[`solution/README.md`](solution/README.md), требования к защищённому развёртыванию
и ограничения — в [`solution/SECURITY_AND_OPERATIONS.md`](solution/SECURITY_AND_OPERATIONS.md).

## MCP-контекст для сопровождения

Мы используем **[Project Context Router](https://github.com/ukolov-dev/mcp-project-context-router)** —
локальный MCP-сервер и CLI для работы с памятью проекта. MCP (Model Context Protocol)
позволяет AI-агенту обращаться к инструментам сервера из своего редактора или приложения.
Код MCP-сервера находится в отдельном репозитории по ссылке выше, а знания именно об
этом решении — в [`.project-context/`](.project-context/README.md), рядом с кодом сервиса.

### Для чего он нужен

В контексте сохранены исходные материалы, требования, регламент хакатона и
подготовленные документы. Маршрутизатор помогает агенту:

- находить требования и связанные с ними источники;
- собирать нужные материалы под конкретный вопрос или задачу;
- находить существующую реализацию перед изменением кода;
- объяснять устройство решения и помогать с его сопровождением.

Организаторы и новые разработчики могут открыть проект с подключённым MCP и
задавать агенту вопросы о реализации, опираясь на сохранённый контекст и текущий код.
Фактическое поведение следует сверять с кодом и тестами: импортированные документы
могут описывать более раннее состояние проекта. Начните с [`START_HERE.md`](START_HERE.md).

### Установка и подключение

Понадобятся **Node.js 22.13 или новее**, npm и клиент с поддержкой локальных MCP-серверов
через stdio. Выполните команды из **корня `pii-safety-module`**, где находится `package.json`
(если после запуска сервиса вы остались в `solution/`, сначала выполните `cd ..`):

```bash
npm ci
npm run context:index
npm run context:doctor
```

`npm ci` устанавливает версию маршрутизатора, закреплённую в `package-lock.json`.
Индекс строится локально по записям контекста. Повторная инициализация или импорт
для этого репозитория не требуются.

**Codex:** конфигурация уже включена в [`.codex/config.toml`](.codex/config.toml).
Откройте корень репозитория как доверенный проект и перезапустите клиент после
установки зависимостей. В списке MCP-серверов должен появиться `project_context`.
Используется профиль `analyst`: он включает поиск требований, работу с источниками
и сбор контекста для разработки. Подробности — в
[инструкции подключения к Codex](https://github.com/ukolov-dev/mcp-project-context-router/blob/main/docs/install/codex.md).

**OpenCode:** подключите тот же сервер по
[инструкции на русском](https://github.com/ukolov-dev/mcp-project-context-router/blob/main/docs/install/opencode.ru.md).
Рабочей директорией сервера должен быть корень этого решения, чтобы он читал нашу
папку `.project-context/`.

### Как пользоваться

После подключения попросите агента, например:

> Используй MCP project_context: найди требования к маскированию, затем покажи,
> где они реализованы в коде и какими тестами проверяются. Приведи ссылки на источники.

> Собери контекст для сопровождения сервиса и объясни, как устроено восстановление
> персональных данных и где хранится соответствие масок исходным значениям.

Без MCP-клиента можно искать материалы через CLI из корня репозитория:

```bash
npx project-context search "маскирование"
npx project-context --help
```

Подробнее о работе с задачами и знаниями — в
[руководстве Project Context Router](https://github.com/ukolov-dev/mcp-project-context-router/blob/main/docs/workflow.ru.md).
Локальные окружения, кэши, секреты и ZIP-сборки в репозиторий не включаются.

## Структура репозитория

- `solution/` — исходный код, Docker Compose, тесты и результаты проверок.
- `.project-context/active/` — исходные тексты, требования, регламент хакатона, подготовленные документы и контекст для агента.
- [Указатель материалов](.project-context/SOURCE_MAP.md) — соответствие 87 исторических путей записям контекста.
- `RAW/ds.pdf` — PDF-источник, отсутствующий в текстовом импорте.
- `playbooks/` — процедуры обработки источников и требований.

Дубли текстовых материалов из `RAW/`, `database/`, `hackathon_database/` и `COOKED/` исключены после сверки содержимого. Исторические пути внутри импортированных документов разрешаются через указатель материалов. Команда `context:import` предназначена для исходного рабочего архива и в публичной версии заблокирована; используйте `context:index` для построения индекса.
