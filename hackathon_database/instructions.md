# Инструкции для участников (база знаний хакатона)

Инструкции и организационные материалы для участников. Собирается из чанков и источников.

## Инструкции
### Упаковка решения в ZIP
- Упаковывайте только исходный код решения.
- Не добавляйте объёмные файлы: датасеты, дампы, архивы, медиа, скомпилированные бинарники.
- Не упаковывайте каталоги зависимостей: node_modules, .venv, venv, env.
- Не упаковывайте каталоги сборки: target, build, dist, out, bin, obj.
- Не упаковывайте служебные каталоги: .git, .idea, __pycache__, .coverage.
- Один архив в формате ZIP разумного размера, с исходным кодом в корне или в понятной структуре.

### Нагрузочное тестирование
- Развернуть решение, реализующее контракт API с эндпоинтом POST /process.
- Обеспечить доступность по указанному URL на время прогона.
- Контракт API — Приложение A, инструкция по прохождению проверки — Приложение B (в ds.pdf).

### Промежуточная проверка
- В кабинете доступна форма проверки ZIP-архива и развёрнутого решения до окончания хакатона.
- Интерфейс показывает остаток общих и успешных попыток. Значения динамические; 23.09.2026 в просмотренном кабинете отображалось 48/48.

### Финальная отправка
- Краткое описание решения: до 1000 символов.
- Архив с кодом: обязателен, не более 2 Гб.
- Презентация: обязательна, не более 50 Мб.
- Ссылка на VCS: обязательна.
- Ссылка на развёрнутое решение: обязательна.
- Скринкаст: не помечен как обязательный; лимиты — до 1 Гб и до 3 минут.
- Решение можно отправлять несколько раз; перед повторной загрузкой файлов страницу рекомендовано обновить.

### Инструменты
- Модель для разработки: DeepSeek V4 Flash (доступ предоставлен на 39 часов).
- IDE: VS Code, Kilo Code.
- Чат поддержки для вопросов и консультаций.
- Рекомендуемые языки: Python, Java, Go (рекомендация из брифинга).

### Описание использования EVC и скиллов
- На втором этапе жюри смотрит на архитектуру и способы создания приложения с точки зрения EVC (Enterprise Vibe Coding).
- Рекомендуется в описании решения подсветить, как использовались инструменты EVC и скиллы, сделать большое описание.
- Рекомендуется приложить README и инструкцию для жюри по проверке.

## Организационные материалы
- Инфраструктура для нагрузочного тестирования — на стороне участников; организаторы мощности не предоставляют.
- Система автопроверки принимает практически любые URL (можно поднять туннель для локального решения). При использовании туннеля нужно уведомить организаторов.
- Промежуточная автопроверка доступна в портале; вопрос Q-001 закрыт по подтверждению SRC-005.
- Рекомендуется разворачивать решение на российских серверах.
- Для локального запуска у жюри ориентир: от 4 до 6 ядер CPU, около 8 ГБ RAM, без обязательного GPU. Это ориентир для локального запуска, а не ограничение серверной инфраструктуры.

## Отсутствующие материалы
- Обещанные отдельные файлы с критериями оценки (шорт-лист, чек-лист) не входят в полученные материалы — организаторы должны прислать их в чат участников.
