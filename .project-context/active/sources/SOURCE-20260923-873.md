# Поддержание трассируемости

Процедура ведения матрицы трассируемости: источник > чанк > требование > задача > критерий > результат проверки.

## Матрица трассируемости
Матрица связывает записи по цепочке:
```
SRC-NNN > CH-SRC-NNN-NN > REQ-001 > TASK-001 > AC-001 > RES-001 (конкретная проверка)
```
Поддерживает несколько задач на требование и повторные проверки одного критерия. ID — по `database/working/id_rules.md`.

## Место сохранения
Результат сохраняй в `database/working/traceability_matrix.md`.

## Правила
- Связывай только **реально существующие** записи.
- Отсутствующую задачу или проверку не придумывай — оставляй ячейку пустой.
- Один критерий может иметь несколько задач и повторных проверок (`RES-`).
- Каждая повторная проверка имеет собственный `RES-` и сохраняет историю предыдущих результатов.
- При изменении требования показывай затронутые документы и задачи.

## Формат записи
```yaml
REQ-001:
  источник: SRC-NNN
  чанк: CH-SRC-NNN-NN
  задачи:
    - TASK-ID: <TASK-001>
      критерии:
        - AC-ID: <AC-001>
          проверки:
            - RESULT-ID: <RES-001>
              статус: <принято | провалено | заблокировано | не проверялось>
```

## Порядок работы
1. При добавлении/изменении требования обнови матрицу.
2. Связывай только существующие записи.
3. При изменении требования покажи затронутые документы и задачи.
4. После значимых изменений обновляй `database/current_context.md`.
