# Правила идентификаторов

Единые правила выдачи ID для требований, задач, критериев, чеклистов и результатов проверок.

## Пространства ID

| Тип | Префикс | Пример | Область уникальности |
| --- | --- | --- | --- |
| Требование | `REQ-` | `REQ-001` | глобально |
| Задача | `TASK-` | `TASK-001` | глобально |
| Критерий приемки | `AC-` | `AC-001` | глобально |
| Чеклист | `CHK-` | `CHK-001` | глобально |
| Результат проверки | `RES-` | `RES-001` | глобально |

## Порядок выдачи следующего номера
- Номер — трёхзначный с ведущими нулями (`001`, `002`, ...).
- Следующий номер = максимальный занятый номер в пространстве + 1.
- Перед созданием проверяй занятые идентификаторы в соответствующем реестре/индексе.

## Правила
- Старые идентификаторы не перенумеровывай.
- Занятые идентификаторы не используй повторно.
- Каждая повторная проверка критерия получает собственный `RES-` и сохраняет историю предыдущих результатов.
- При доработках задачи сохраняй трек, номер и название.

## Связанные пространства (не входят в эту схему)
- Источники: `SRC-NNN` (см. `registry_sources.md`).
- Чанки: `CH-SRC-NNN-NN` (см. `chunks/index.md`).
- Решения: `DEC-NNN`, вопросы: `Q-NNN`, конфликты: `CONF-NNN`, покрытие: `COV-NNN` (см. реестры).
- **Область уникальности DEC/Q/CONF/COV — в пределах каждой базы знаний** (`database/` и `hackathon_database/` независимы). При перекрёстной ссылке указывай базу (например, `hackathon_database/Q-001`).
