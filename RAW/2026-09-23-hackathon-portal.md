# Снимок портала хакатона

> Ручная текстовая фиксация страниц, просмотренных в авторизованном кабинете участника 23.09.2026. Учётные данные не сохранялись.

## Страница «Проверка решения»

- URL: https://reg.vibecoding-hackathon.ru/results/data-science
- Трек: «Высоконагруженный прокси для LLM».
- Назначение: раздел для проверки архива с кодом.
- Доступно до 23 сентября 23:59, UTC+03:00.
- Период загрузки: с 22.09.2026 09:00 МСК до 23.09.2026 23:59 МСК.
- Для запуска проверки требуются ZIP-архив и ссылка на развёрнутое решение.
- На момент просмотра кабинет показывал: «Любых попыток осталось: 48» и «Успешных попыток осталось: 48». Это динамическое состояние конкретного кабинета, а не общий лимит из регламента.
- Портал повторяет требования о том, что архив должен иметь формат ZIP и содержать только исходный код, а для нагрузочной проверки нужен доступный `POST /process`.
- Описание задачи на странице по существу совпадает с онбордингом `RAW/Сегодня_все_команды,_работающие_с_L.txt`: типы ПД, маскирование/демаскирование, качество 95%, контекст до 100 000 токенов, latency до 1 с и RPS 1000.

## Страница «Загрузка решения»

- URL: https://reg.vibecoding-hackathon.ru/results/submitsolution
- Страница указывает, что решение можно отправлять несколько раз; перед повторной загрузкой файлов рекомендуется обновить страницу.
- Поля формы:
  - краткое описание решения — текст до 1000 символов;
  - архив с кодом решения — обязательно, не более 2 Гб;
  - презентация решения — обязательно, не более 50 Мб;
  - скринкаст решения — без маркера обязательности, не более 1 Гб и 3 минут;
  - ссылка на VCS — обязательно;
  - ссылка на развёрнутое решение — обязательно.

## Страница «Задача»

- URL: https://reg.vibecoding-hackathon.ru/tasks
- Название: «Высоконагруженный прокси для LLM».
- Краткая формулировка: «Выстроить взаимодействие с моделью так, чтобы данные обрабатывались на лету — без шаблонов, с полным погружением в контекст задачи».
- Акценты: SLA по времени отклика, отказоустойчивость, масштабируемость, гибкость к изменениям и кратный рост нагрузки.
- Полное описание портал отсылает читать в разделе «Хакатон → Проверка решения».

## Результат сверки

- Основные требования к системе не изменились и подтверждают `SRC-001`..`SRC-004`.
- Новая регламентная информация: точные поля и лимиты финальной формы, возможность повторной отправки и наличие счётчиков попыток.
- Фраза «без шаблонов» не уточняет, какие именно технические подходы запрещены; она зафиксирована как описательный акцент, а не как новое согласованное требование.
