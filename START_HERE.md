# START_HERE — порядок работы

Точка входа для нового агента. Прочитай этот файл, затем `AGENTS.md`, `.project-context/active/sources/SOURCE-20260923-124.md` и `PROJECT.yaml`.

## Быстрый старт
1. `START_HERE.md` — этот файл (порядок работы).
2. `AGENTS.md` — правила работы.
3. `.project-context/active/sources/SOURCE-20260923-124.md` — краткое состояние проекта.
4. `PROJECT.yaml` — паспорт проекта.
5. `.project-context/active/sources/SOURCE-20260923-717.md` — маршруты чтения по задаче.

## Общий поток
```
Источники → .project-context/active → .project-context/active/requirements
```

## Контуры работы

### Контур сбора и постановки требований (база знаний)
- Сбор, извлечение и постановка требований.
- Работает с `RAW/`, `database/`, `.project-context/active/requirements/`, `playbooks/`.
- Поток: `RAW → database → .project-context/active/requirements`.
- **Разделение баз знаний**: материалы о регламенте проведения хакатона (правила, инструкции, критерии оценки) → `hackathon_database/`; требования к самой системе → `database/`.

### Контур разработки (документация по коду)
- Разработка и документация программного кода.
- Использует базу знаний как источник требований и контекста.
- Может пополнять базу знаний: новые требования из контура разработки фиксируются через `playbooks/process_source.md` и `playbooks/manage_requirements.md`, а не вносятся напрямую в спецификацию.

## Порядок работы по задачам
1. **Обработка источника** → `playbooks/process_source.md` (регистрация → чанки → тематические знания → глоссарий → решения и вопросы → покрытие).

## Правила
- Требования не выдумываются — только извлекаются из источников.
- Каждый факт имеет источник; ссылайся на него.
- Новое обсуждение не отменяет утвержденное требование автоматически.
- Оригиналы сохраняй, существующие изменения не затирай, файлы не удаляй.
- Новая ревизия — сохраняй предыдущую редакцию неизменяемым снимком, `current_specification.md` всегда актуален.
- Обработка источника сама по себе не создает задачи разработки.
- Если не ясно, что делать с файлом — уточни правила обработки, не придумывай процесс сам.
- Язык исходников — русский.
- Неоднозначные фрагменты помечай как открытые вопросы (`Q-NNN`); недосказанность — открытый вопрос, не выдумывай отсебятину.
- Новый источник уточняет предыдущие требования; радикальное изменение — открытый вопрос для разрешения конфликта.
- Проходись по сырому файлу дважды; не ищи явные маркеры, проверяй упущенный контекст.
- Всегда проверяй индекс чанков перед созданием нового чанка.
